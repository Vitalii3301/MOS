# MOS R4.2 Portable — запуск внутри инструментального LLM-чата

Эта сборка не запускает отдельную языковую модель и не требует LLM API.
ChatGPT, Claude или другая хост-LLM формирует ответ сама, а MOS реально
исполняется Python-средой чата до и после ответа.

## Роли компонентов

- GitHub `main`: код, протокол и стартовые файлы MOS.
- GitHub `mos-state`: единое переносимое состояние MOS.
- Code Interpreter: Python-процесс и временная рабочая память.
- Хост-LLM: формирование ответа из проверенного MOS-контекста.

GitHub не является живой файловой системой. Каждый ход выполняет цикл
`fetch -> restore -> begin-turn -> host answer -> commit-turn -> push`.

## Первый запуск в новом чате

```bash
git clone https://github.com/Vitalii3301/MOS.git
cd MOS/runtime/portable
python MOS_VERIFY_GITHUB_STATE.py --repo-root ../..
```

Если GitHub уже подключён к чату, хост может получить репозиторий через
доступный GitHub-коннектор вместо `git clone`.

## Начало хода

Сохраните точный ввод пользователя в UTF-8 файл, затем выполните:

```bash
python MOS_BEGIN_TURN.py \
  --repo-root ../.. \
  --session CHAT_SESSION_ID \
  --text-file user_input.txt \
  --output mos_turn_context.json
```

Команда:

1. загружает `mos-state`;
2. проверяет хеш снимка;
3. восстанавливает SQLite;
4. запускает MOS;
5. выдаёт контекст для встроенной LLM;
6. создаёт локальную незавершённую транзакцию хода.

## Фиксация ответа

Перед тем как показать ответ пользователю, сохраните полный ответ в файл и
выполните:

```bash
python MOS_COMMIT_TURN.py \
  --repo-root ../.. \
  --session CHAT_SESSION_ID \
  --response-file host_answer.txt \
  --host chatgpt-code-interpreter
```

Команда записывает ответ в MOS, проверяет SQLite и цепочку событий, создаёт
новый полный snapshot и публикует его в `mos-state` обычным Git push.

## Доступ к GitHub

Чтение публичного репозитория не требует токена. Для записи требуется один из
вариантов:

- уже настроенный Git/SSH;
- переменная окружения `MOS_GITHUB_TOKEN` с минимальным правом записи;
- GitHub-коннектор хост-чата, использующий локальный publish bundle.

Токен не записывается в состояние, вывод или Git-конфигурацию репозитория.

Если прямой `git push` недоступен, выполните фиксацию с
`--transport bundle`. Команда создаст `BUNDLE.json` и три подготовленных файла.
Хост-чата должен записать их одним коммитом в `mos-state`, проверив
`expected_parent_commit`, после чего подтвердить результат:

```bash
python MOS_ACK_PUBLISH.py --repo-root ../.. --session CHAT_SESSION_ID
```

`MOS_ACK_PUBLISH.py` повторно загружает ветку и принимает публикацию только при
точном совпадении `snapshot_id` и `state_hash`.

## Параллельные чаты

`mos-state` обновляется только fast-forward push. Если два чата стартовали от
одного состояния, первый публикует новый HEAD, а второй не перезаписывает его.
Снимок второго сохраняется в ветке `mos-conflict/<session>/<cycle>`.

## Честные ограничения

- Обычный чат без исполнения Python не запускает MOS.
- Python внутри чата не вызывает встроенную LLM напрямую. Хост сначала
  выполняет `begin-turn`, сам формирует ответ и затем выполняет `commit-turn`.
- Процессы и RAM не переносятся между чатами; переносится полное проверяемое
  состояние MOS.
- Текущий репозиторий публичный. До включения шифрования нельзя публиковать в
  `mos-state` сообщения, которые пользователь не согласен сделать публичными.
